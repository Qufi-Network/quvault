    Post quantum cryptography

    Designed for the
    cryptographic lifecycle ahead.

    Digital assets and the records around them may need to stay secure for years or decades.

    Veyns is built on modern post quantum primitives, with the agility to move as those primitives move.

    • ML-DSA-65

      FIPS 204

      Signs every human authorization, under a context that separates it from every other signature this system makes.

      Implemented

    • ML-KEM-768

      FIPS 203

      Establishes the key that seals the vault, paired with X25519 so the seal holds if either is broken.

      Implemented

    • SLH-DSA

      FIPS 205

      Hash based signatures, resting on the hash alone. Not part of this system today.

      Not implemented

    • Cryptographic agility

      Identity, policy and transactions stay put

      Only the cryptographic layer moves, so an algorithm can be replaced without rebuilding the architecture around it.

      Designed for

    Key protection

    The key never becomes
    an application object.

    An application asks for a signature. It does not receive the key that made it.

    1. ApplicationAsks for an operation
    2. Veyns control planeDecides whether it may happen
    3. Cryptographic trust boundary
    4. Key materialSealed with ML-KEM-768 and X25519
    5. SignatureReturns. The key does not.

    Today the unsealing happens in the browser rather than in dedicated hardware. Moving it behind hardware is what the architecture is designed for, and it is not done yet.

    Architecture

    From intent
    to execution.

    Every transaction passes through each of these before it can execute. Scroll, and the architecture assembles in the order the transaction moves through it.

    1. 01 Initiate

      Asset, amount and destination become a plan the server alone is allowed to make.

    2. 02 Authorize

      A palm read by Veyns, and as many more as the policy requires.

    3. 03 Policy

      Amount, quorum, destination and window, all evaluated before any key is reached for.

    4. 04 Cryptography

      The plan is canonicalised, digested, and that digest is what the approval signs.

    5. 05 Signing

      The spending key is unsealed for one narrow window and signs that plan only.

    6. 06 Execute

      Broadcast, then watched until it confirms.

    7. 07 Evidence

      What was authorized, by whom, under which policy, against which transaction.

    Cryptography

    Built for today.
    Ready for tomorrow.

    Veyns is designed around modern cryptographic primitives with a focus on long term cryptographic resilience and algorithmic agility. Each card says whether the primitive is in the running system.

    • ML-DSA-65

      FIPS 204 · module lattice signatures

      Signs every human authorization, under a context that separates it from every other kind of signature this system makes.

      Implemented

    • ML-KEM-768

      FIPS 203 · module lattice key encapsulation

      Establishes the key that seals the vault, combined with X25519 so the seal holds if either one of the two is broken.

      Implemented

    • SLH-DSA

      FIPS 205 · hash based signatures

      Stateless hash based signatures, whose security rests on the hash alone. Not in this system today.

      Not implemented

    • Hybrid establishment

      ML-KEM-768 + X25519 · HKDF-SHA256

      Both secrets feed one derivation, so the result is no weaker than the stronger of the two.

      Implemented

    Security principles

    Simple principles.
    Strong architecture.

    1. 01Key material stays sealed

      It is unsealed to sign one plan, in one window, and the window closes behind it.

    2. 02Policy precedes signing

      Conditions are evaluated before a key is reached for, not after.

    3. 03People authorize critical actions

      A palm, present, at the moment of signing.

    4. 04Transactions are explicit

      An approval carries the digest of the transaction it approves and no other.

    5. 05Security is verifiable

      What was authorized, by whom and under which policy, recorded and readable.
